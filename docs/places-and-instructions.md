# Места, клиенты и инструкции

## Справочник мест

**Место** — склад, клиент, таможенный пост, порт, стоянка. Это постоянная
сущность, а этап рейса на неё **ссылается**. То, что известно о месте,
вводится один раз и подтягивается в каждый рейс.

```
Place
  id, external_id, name
  address, lat, lon, timezone
  kind?                    склад / клиент / таможня / порт / граница / стоянка ...
  working_hours?           часы работы, перерывы
  contacts[]               { name, phone, role }   «Ашот, охрана»
  instructions[]           постоянные инструкции места (см. ниже)
  tags[]                   например #reefer_only, #appointment_required
```

Зачем это нужно:

- **Инструкции не вводятся заново** в каждый рейс.
- **Отчёты по местам:** средний простой на складе, выполнение окон,
  частота конфликтов и нарушений.
- **Интеграции** присылают ссылку на место по `external_id` и не дублируют
  адрес и контакты.

Этап может ссылаться на место (`place_id`) или содержать адрес напрямую,
если место разовое.

## Клиенты и их требования

**Клиент** (заказчик, грузоотправитель, грузополучатель) — тоже постоянная
сущность. У рейса есть `customer_id`.

У клиента обычно есть свои **требования к перевозке**: к погрузке, к
выгрузке, к машине и водителю. В системе они превращаются в обычные
инструкции и требования этапа, отдельного механизма не нужно:

| Требование клиента | Чем становится |
|---|---|
| «Не ставить в 2 яруса» | инструкция с «Ознакомлен» до «Начато» |
| «Температура +2…+6» | требование «температура» до «Убыл» |
| «24 ремня, крепить каждые 2 ряда» | требование-чек-лист и фото крепления до «Убыл» |
| «Кузов чистый, без запаха» | требование «фото кузова» до «Начато» |
| «Водитель в спецодежде и каске» | инструкция при прибытии |

### Правила с условиями

Инструкции и требования попадают на этап по **правилам**. У правила есть
условия, все необязательные:

| Условие | Пример |
|---|---|
| тип этапа | только погрузки |
| теги | только рейсы с `#reefer` |
| **клиент** | только рейсы клиента X |
| **место** | только этапы на складе «Северный» |

Требования клиента — это правила с условием «клиент = X». В интерфейсе они
редактируются **в карточке клиента**: «у клиента X на погрузке: не выше 2
ярусов, 24 ремня, фото крепления». Так же требования склада (например, фото
пропуска) редактируются в карточке места.

Требования **конкретной заявки** (особая температура только в этом рейсе)
приходят разово вместе с рейсом через API или задаются диспетчером.

В каждом требовании и инструкции на этапе видно, **откуда оно взялось**:
от клиента, места, тега, типа этапа или вручную.

## Инструкции

**Инструкция — то, что водитель должен знать.** **Требование — то, что он
должен сделать или предоставить** (см.
[events-and-requirements.md](events-and-requirements.md)).

### Виды

| Вид | Пример |
|---|---|
| `text` | «Приедешь — позвони Ашоту, он откроет ворота» |
| `contact` | Ашот, +7…, кнопка «Позвонить» |
| `photo` | фото въезда, ворот, рампы |
| `location` | точка въезда для грузовых, если она не совпадает с адресом |
| `file` | схема проезда, пропуск, доверенность |
| `voice` | голосовое пояснение диспетчера |
| `link` | ссылка, например запись на слот |

### Когда показывать (`show_at`)

| Значение | Когда водитель видит |
|---|---|
| `always` | сразу, как только получил рейс (схема проезда, пропуск) |
| `arrived` | после «Прибыл»: всплывает на экране («Позвони Ашоту») |
| `started` | с начала работы («Не грузить выше 2 ярусов») |
| `completed` | после окончания работы, перед убытием («Не уезжай без второго экземпляра CMR») |

Инструкцию из более поздней фазы водитель может открыть и заранее, но
приложение само показывает её в нужный момент.

### Подтверждение «Ознакомлен»

У инструкции можно включить подтверждение до определённой фазы
(`ack_before_phase`). Тогда:

- на этапе автоматически появляется **требование вида «ознакомлен»**;
- водитель нажимает «Ознакомлен», и это обычное уточняющее событие
  `instruction_acknowledged`;
- требование работает как любое другое: блокирует переход, его можно снять,
  без связи можно пройти с нарушением.

Например, нельзя нажать «Начато», пока не подтверждено «Не загружать выше
2 ярусов».

### Откуда берутся инструкции на этапе

Как и требования, они **складываются** из нескольких источников:

1. **Место:** постоянные инструкции склада (Ашот, ворота, часы работы).
2. **Тип этапа и теги:** например, для `#adr` — «Не останавливаться у
   жилых домов».
3. **Конкретный этап:** разовые инструкции от диспетчера или через API
   («Сегодня Ашота нет, звони Вове»).

### Изменение во время рейса

- Каждая инструкция на этапе хранит **номер редакции**.
- При изменении редакция растёт, водитель получает уведомление и карточку
  в чате рейса.
- Если у инструкции включено подтверждение, прежнее «Ознакомлен» больше не
  засчитывается, и водитель подтверждает её заново.

### Как это выглядит у водителя

```
┌ Погрузка · Склад «Северный» ──────────────────────────┐
│ 📞 Ашот (охрана)  +7 900 000-00-00     [Позвонить]     │
│ 📝 Приедешь — позвони Ашоту, он откроет ворота         │
│ 🖼 Фото въезда                                          │
│ ⚠ Не грузить выше 2 ярусов       [Ознакомлен]          │
└───────────────────────────────────────────────────────┘
```
