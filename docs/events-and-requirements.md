# События и требования

Для каждого события задаётся:

1. **Где** его можно выставить. Это область применения, в интерфейсе она
   показывается ярлыками.
2. **Что** оно требует от водителя в момент выставления. Это поля события.

Отдельно от событий у каждого этапа есть **список требований** — всё, что
водитель должен на этом этапе увидеть и выполнить: прочитать («позвони
Ашоту»), подтвердить («не грузить выше 2 ярусов»), сфотографировать,
приложить документ.

Всё это проверяется общим модулем и на сервере, и на телефоне, в том числе
без связи.

## 1. Область применения события (ярлыки)

Событие доступно водителю, только если подходят **все** его ярлыки. Пустой
ярлык означает «без ограничений».

| Ярлык | Что ограничивает | Пример |
|---|---|---|
| **Вид этапа** | точка / транзит | `Остановка` — только транзит |
| **Тип этапа** | конкретные типы | `Начало погрузки` — только `loading` |
| **Вид транзита** | road / ferry / rail | `Отплытие` — только ferry, rail |
| **Фаза** | в каких фазах доступно | `Документы получены` — в фазе «Завершено» |
| **Роль** | водитель / диспетчер / наблюдатель / интеграция | `Простой подтверждён` — только диспетчер |
| **Исполнитель** | только исполнитель этапа или любой водитель рейса | при смене водителя событие ставит только новый |
| **Теги рейса / этапа** | нужен тег или, наоборот, тег запрещён | `Температура рефа` — только с тегом `#reefer` |

**Теги** — свободные метки, которые ставятся на рейс или этап вручную либо
через API: `#reefer`, `#adr`, `#customs`, `#food`, `#high_value`,
`#unaccompanied`. С их помощью одно и то же событие или требование
включается только там, где оно нужно, без отдельного типа этапа на каждый
случай.

В админке ярлыки показываются прямо на карточке события:

```
┌ Документы получены ───────────────────────────────────────────┐
│ [Точка] [Погрузка] [Выгрузка] [Фаза: Завершено] [Водитель]   │
│ Требует: фото документа ×1–5 (камера) · номер CMR             │
└───────────────────────────────────────────────────────────────┘
```

## 2. Что событие требует от водителя (поля события)

Это форма, которая открывается при нажатии кнопки события.

| Вид поля | Настройки |
|---|---|
| `photo` | мин / макс, **только камера** или камера и галерея |
| `video` | макс длительность |
| `document` | многостраничный скан (камера с обрезкой) |
| `signature` | подпись на экране (грузополучатель, кладовщик) и ФИО подписавшего |
| `scan` | штрихкод / QR: пломба, паллетные этикетки, номер прицепа |
| `number` | единица, мин / макс (температура, вес, паллеты, пробег) |
| `text` | многострочный, мин длина |
| `select` / `multiselect` | список вариантов (причина задержки) |
| `datetime` | новое ETA, время слота |
| `checklist` | набор галочек («груз закреплён», «ремни на месте») |

У каждого поля можно задать:

- `required` — обязательно ли поле;
- `show_if` — условие показа, например «Комментарий обязателен, если
  причина — Прочее».

Автоматически, без участия водителя, сохраняются:

- время события;
- GPS и точность;
- у каждого фото — время съёмки, координаты и **источник** (камера
  приложения или галерея).

Фото из галереи можно запретить или разрешить с пометкой: это защита от
«вчерашних» снимков.

## 3. Требования этапа

**Требование — один пункт на этапе, который водитель видит и с которым
работает.** Отдельных «инструкций» нет: инструкция — это требование вида
«прочитать».

### Виды

| Вид | Что делает водитель | Пример |
|---|---|---|
| `info` | читает | «Приедешь — позвони Ашоту, он откроет ворота» |
| `acknowledgement` | читает и нажимает «Ознакомлен» | «Не грузить выше 2 ярусов» |
| `photo` / `video` | снимает | фото процесса погрузки, фото крепления |
| `document` | снимает документ | подписанная CMR |
| `signature` | берёт подпись на экране | подпись получателя |
| `scan` | сканирует или вводит код | номер пломбы |
| `number` / `text` | вводит значение | температура рефа |
| `checklist` | отмечает пункты | «ремни на месте», «упоры стоят» |
| `event` | выставляет событие | «Пломба установлена» |

К любому требованию можно приложить пояснение: текст, **контакт** с
кнопкой «Позвонить», **точку на карте**, **фото или файл** (схема проезда,
фото ворот, голосовое), ссылку.

### Описание требования

```
StageRequirement
  title                  «Фото крепления ремнями»
  kind                   см. таблицу выше
  text?, contact?, location?, attachment_ids[]?, url?   пояснение
  show_at                когда показывать: always | arrived | started | completed  (по умолчанию always)
  before_phase           до какой фазы выполнить; для info не нужен
  min / max              например, фото ≥ 2
  capture_from_phase     засчитывается собранное начиная с этой фазы (например, с «Начато»)
  camera_only            только камера приложения, не галерея
  event_type / value_key для kind = event / scan / number ...
  strictness             block — не пускает в фазу (по умолчанию) | warn — пускает, но отмечает
  waivable               может ли диспетчер снять (по умолчанию да)
  revision               растёт при изменении; «Ознакомлен» засчитывается только для текущей
```

### Откуда берутся требования на этапе

1. **Вместе с этапом** — через API при создании рейса или от диспетчера.
   Это основной путь: требования заявки, особенности склада, просьбы
   клиента. Всё, что нужно знать и сделать на этой точке, кладётся прямо в
   этап.
2. **По умолчанию для типа этапа** из справочника. Например, у каждой
   погрузки фото процесса, пломба и CMR, а для рейсов с тегом `#reefer` ещё
   и температура. Чтобы не повторять одно и то же в каждом рейсе.

Оба вида лежат в **одном списке** этапа, и для водителя между ними нет
разницы.

### Когда водитель видит требование

| `show_at` | Когда |
|---|---|
| `always` | сразу, как только получил рейс (схема проезда, пропуск) |
| `arrived` | после «Прибыл»: всплывает на экране («Позвони Ашоту») |
| `started` | с начала работы |
| `completed` | после окончания работы, перед убытием |

### Как это выглядит у водителя

```
┌ Погрузка · Склад «Северный» ──────────────────────────────┐
│ 📞 Позвони Ашоту, он откроет ворота   [Позвонить]          │
│ ⚠ Не грузить выше 2 ярусов            [Ознакомлен]         │
│ 📷 Фото процесса погрузки             2 / 3                │
│ 📷 Фото крепления ремнями             0 / 2  [Снять]       │
│ 🔢 Номер пломбы                       —      [Сканировать] │
│ 📄 Подписанная CMR                    —      [Снять]       │
└───────────────────────────────────────────────────────────┘
```

1. Требования видны в карточке этапа **сразу**, водитель заранее знает,
   что придётся сделать.
2. По ходу работы фото добавляются через **«Фото процесса»**, счётчик
   растёт.
3. При нажатии «Начато» или «Убыл» открывается **чек-лист перехода** с
   тем, что ещё не выполнено. Недостающее можно снять прямо из него.
4. Требования `block` не пускают в фазу. Если выполнить невозможно,
   водитель нажимает **«Не могу выполнить»** с причиной, и диспетчер снимает
   требование одним нажатием.
5. **Офлайн:** если требование выполнить нельзя, а связи нет, водитель
   может перейти в фазу **с нарушением**. Событие помечается, и диспетчер
   увидит это, когда событие дойдёт.
6. **Убыл без работы** («груз не готов», с причиной): требования к работе
   получают отметку «неприменимо». Это не нарушение.
7. **Изменение во время рейса:** если диспетчер поменял требование, растёт
   его редакция, водитель получает уведомление, а «Ознакомлен» нужно
   нажать заново.

### Как это выглядит у диспетчера

- На этапе видно, что выполнено, чем (с превью фото) и когда.
- Можно добавить требование на этап, изменить его, снять или пометить
  «не требуется» с причиной.
- Нарушения (`warn`, снятые требования, переходы офлайн с нарушением)
  попадают в отдельный фильтр и отчёт.

## 4. Где это видно в админке

- **Справочник событий**: карточка с ярлыками и полями, предпросмотр формы
  глазами водителя.
- **Требования по умолчанию** для типов этапов и тегов.
- **Раздел «Автоматы»**: на каждом переходе фазы подписаны требования
  по умолчанию (см. [state-machine.md](state-machine.md#автоматы-в-админке)).
- **Симулятор** показывает, что заблокирует переход для выбранного рейса.
