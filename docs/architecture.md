# Архитектура и развёртывание

## Общая схема

```
          ┌──────────────────────── сервер клиента ────────────────────────┐
          │                                                                │
 PWA  ───►│  reverse proxy (TLS)  ──►  plobi-app (API + WebSocket + PWA)   │
(водитель,│                                  │            │                │
 диспетчер)                                  ▼            ▼                │
          │                            PostgreSQL    файловое хранилище    │
 TMS/1С/  │                                          (том или S3/MinIO)    │
 ERP  ───►│  REST API (токены интеграций)                                  │
          │  ◄── вебхуки об изменениях ───                                 │
          └────────────────────────────────────────────────────────────────┘
```

Один контейнер `plobi-app` отдаёт и API, и статику PWA. Минимальная поставка
состоит из `docker-compose.yml` с тремя сервисами: `app`, `postgres` и
(необязательно) `minio`. Если MinIO не нужен, файлы хранятся в Docker-томе.

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Бэкенд | TypeScript, Node.js, Fastify | один язык с фронтендом, быстрый, хорошая генерация OpenAPI |
| БД | PostgreSQL 16 | надёжная, JSONB для пользовательских полей, у клиентов обычно уже есть опыт |
| ORM и миграции | Drizzle ORM | типобезопасность, SQL-миграции применяются автоматически при старте контейнера |
| Realtime | WebSocket | чат, новые события, статусы «прочитано» |
| Фронтенд | React, Vite, vite-plugin-pwa | PWA «из коробки», service worker |
| Офлайн на клиенте | IndexedDB (Dexie) | очередь неотправленных событий и сообщений, кэш рейса |
| Push | Web Push (VAPID) | работает без Google и Apple-аккаунтов разработчика; ключи генерируются на сервере клиента |
| Файлы | S3-совместимое API или локальный диск | фото, документы, голосовые |

## Self-hosted и лицензирование

- Разработчик не получает никаких данных: нет телеметрии, нет «звонков домой».
- Лицензия — подписанный файл (JWT, Ed25519) с названием компании, сроком и
  лимитом активных пользователей. Приложение проверяет подпись встроенным
  публичным ключом, поэтому интернет для проверки не нужен.
- Обновления: новый тег образа. Миграции БД применяются при старте.
- Резервное копирование (`pg_dump` и том с файлами) лежит на клиенте; в
  документации поставки будет готовый скрипт.

## Офлайн-режим водителя

Связь на трассе пропадает, поэтому:

1. Каждое событие и сообщение получает UUID **на клиенте** и хранит время
   `occurred_at` и координаты на момент действия.
2. Запись сначала попадает в IndexedDB, затем фоново отправляется на сервер.
3. Сервер принимает запись идемпотентно (повтор с тем же UUID не создаёт
   дубль) и дополнительно сохраняет `received_at`.
4. Диспетчер видит оба времени: когда событие произошло и когда оно дошло.

## Ограничения PWA, о которых нужно знать

- **Фоновое отслеживание GPS в PWA невозможно.** Геопозиция снимается только в
  момент действия водителя (событие, сообщение) или пока приложение открыто.
  Для непрерывного трекинга нужны данные с бортового GPS-трекера, их можно
  передавать через API. Если позже понадобится трекинг с телефона, можно
  обернуть PWA в нативную оболочку (Capacitor) без переписывания.
- **iOS:** push-уведомления работают только у PWA, установленного на домашний
  экран (iOS 16.4+).
- Фоновая синхронизация (Background Sync) есть в Android и Chrome. На iOS
  очередь отправляется при следующем открытии приложения.

## Безопасность

- Пароли хранятся как хэши Argon2id. Сессии — короткий access-токен и
  refresh-токен.
- Можно подключить вход через корпоративный SSO (OIDC), это есть в плане работ.
- У каждой интеграции свой API-токен с набором разрешений (scopes).
- Журнал аудита: кто, что и когда изменил.
