# @plobi/server

Сервер Plobi: REST API, вычисление рейсов через `@plobi/core`, PostgreSQL.

```
src/
  main.ts              запуск
  app.ts               сборка приложения: платформа, затем модули
  platform/            конфиг, БД и миграции, ошибки, авторизация, шина событий
  modules/
    identity/          пользователи, роли, сессии (Bearer), первый админ
    catalog/           справочник в БД + базовый набор, проверка изменений
    directory/         места, клиенты, требования клиента
    trips/             рейсы, этапы, журнал событий (онлайн и офлайн-пакеты)
    automata/          схемы автоматов, карта типа этапа, симулятор
drizzle/               SQL-миграции (только вперёд)
test/                  интеграционные тесты на реальной PostgreSQL
```

## Переменные окружения

| Переменная | По умолчанию | |
|---|---|---|
| `DATABASE_URL` | — | обязательна |
| `PORT` / `HOST` | `8080` / `0.0.0.0` | |
| `ADMIN_LOGIN` / `ADMIN_PASSWORD` | `admin` / случайный | первый админ; случайный пароль печатается в лог один раз |
| `SESSION_TTL_HOURS` | `720` | срок сессии |
| `MIGRATIONS_DIR` | `./drizzle` | |
| `LOG_LEVEL` | `info` | |

## Разработка

```bash
DATABASE_URL=postgres://plobi:plobi@localhost:5432/plobi pnpm dev
```

Тесты используют отдельную базу (`TEST_DATABASE_URL`, по умолчанию
`postgres://plobi:plobi@localhost:5432/plobi_test`) и пересоздают её схему:

```bash
pnpm test
```

Новая миграция после изменения `schema.ts` в модуле:

```bash
pnpm db:generate --name <что_изменилось>
```

## Главные принципы

- **Журнал событий — источник истины.** Фаза и состояние не хранятся, а
  вычисляются ядром при чтении. Поэтому запоздавшее офлайн-событие просто
  встаёт на своё место по времени.
- **Онлайн** (`POST /trips/:id/events`): событие, которое не вписывается в
  автомат или ломает уже принятые события, получает 409 и не сохраняется.
- **Офлайн** (`POST /events/batch`): сохраняется всё, неподходящее
  помечается конфликтом для диспетчера.
- **Автор события** — всегда вошедший пользователь, не поле запроса.
- Параллельные события одного рейса упорядочиваются блокировкой строки рейса.
