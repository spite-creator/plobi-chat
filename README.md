# Plobi Chat

Корпоративный мессенджер для логистических компаний: чаты между водителями,
диспетчерами и любыми сотрудниками плюс модуль рейсов с этапами,
требованиями и событиями. Работает на сервере компании и через зеркала,
поэтому не зависит от блокировок публичных мессенджеров.

## Принципы продукта

1. **Self-hosted.** Продаётся как Docker-образ. Каждая компания разворачивает
   его у себя, и все данные остаются на её серверах. Разработчик продукта не
   хранит и не видит данные клиентов.
2. **API-first.** Всё, что можно сделать в интерфейсе, можно сделать через API:
   загрузить рейсы, создать пользователей и чаты, отправить сообщение,
   выставить событие. Встроенного маршрутизатора нет: маршрут приходит готовым
   из внешней системы (TMS, 1С, ERP) или создаётся вручную.
3. **PWA.** Одно веб-приложение для водителя и диспетчера. Его можно
   установить на телефон и пользоваться без магазинов приложений.
4. **Настраиваемость.** Есть базовый набор типов этапов и событий. Компания
   может добавлять свои, причём у каждой роли свой перечень событий.
5. **Без географических ограничений.** Мультиязычность, часовые пояса, время в
   UTC, международные документы.

## Запуск

### Поставка (Docker)

```bash
cp .env.example .env        # задать DB_PASSWORD и ADMIN_PASSWORD
docker compose up -d
```

Два контейнера: `plobi-app` (приложение) и `plobi-db` (PostgreSQL, данные в
томе `db-data`). Вместо `plobi-db` можно указать свою PostgreSQL через
`DATABASE_URL`. Если Docker Hub недоступен, базовый образ задаётся
параметром сборки `NODE_IMAGE` (зеркало реестра).

API: `http://<сервер>:8080/api/v1`, документация — `/api/docs`.

### Разработка

```bash
pnpm install
pnpm test                   # ядро и сервер (серверу нужна PostgreSQL, см. apps/server/README.md)
```

## Структура

```
packages/core   ядро: автоматы, ярлыки, требования (без БД и сети)
apps/server     сервер: модули identity, catalog, places, trips, automata
docs/           документация продукта
```
